# Product

## Register

product

## Users
A broad technical audience uses this product: developers, automation operators, QA and workflow testers, and small teams coordinating agent-assisted work. The primary default user is an operator supervising multiple agents and reviewing their work, but the system also supports code editing, browser automation, desktop automation, and execution oversight.

## Product Purpose
V.E.L.O.C.I.T.Y. is a native control surface for high-trust agentic work. It helps users plan, launch, supervise, and review coding, browser, and Windows automation tasks from one place. The modern interface features an activity bar system with 8 categories, a task-centric sidebar, chat-centric interaction with model selection, and 5 color palettes. Success means the interface feels fast, clean, and well-organized while making complex multi-agent work legible, steerable, and safe.

## Brand Personality
Fast, clean, well-organized. The product should feel expert, operational, and calm under load. It should communicate confidence and control rather than spectacle.

## Anti-references
It should not feel flashy or animated for the sake of it. Avoid toy-like gamification, decorative motion, overloaded dashboards, or an over-styled cyberpunk IDE aesthetic. Avoid making serious automation workflows feel like a hobbyist terminal toy.

## Design Principles
- Make supervision first-class: users should always understand what agents are doing, what is blocked, and where intervention is needed.
- Organize by intent, not implementation: surfaces should reflect user goals like coding, browser automation, desktop automation, and review rather than internal subsystems.
- Keep high-power workflows legible: dense information is acceptable when it is structured, scannable, and prioritized.
- Preserve trust with evidence: automation and agent actions should expose artifacts, diffs, history, and approvals clearly.
- Optimize for fast control: common actions should require minimal navigation and minimal cognitive overhead.

## Accessibility & Inclusion
Target WCAG 2.1 AA as the default accessibility bar. Support reduced motion, strong text contrast, keyboard-first operation, clear focus states, and color usage that does not carry meaning alone. Dense expert workflows should remain readable under fatigue and on lower-quality displays.
